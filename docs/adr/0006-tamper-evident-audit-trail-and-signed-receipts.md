# A tamper-evident Audit Trail and signed Verification Receipts

ADR-0004 makes the Audit Trail insert-only with database triggers, but anyone who can drop the triggers could still rewrite it. Each event now also stores a SHA-256 hash chained to the previous event of its Call, so an edited or deleted event is found and named on any later check. A closed Call's result is handed to core banking as a Verification Receipt: a JWT signed with Ed25519 (a standard any bank system can verify with an off-the-shelf JWT library) that carries the Verdict, the Outcome, whether the Request may be carried out, and the Audit Trail's head hash, so a receipt also stops verifying if the trail behind it changes. We chose per-Call chains over one global chain so parallel Calls never wait on each other; deleting a Call's newest events is caught by the receipt rather than the chain. The signing key lives on the verifier laptop (`data/keys/`, git-ignored); a hardware key store is the production answer.
